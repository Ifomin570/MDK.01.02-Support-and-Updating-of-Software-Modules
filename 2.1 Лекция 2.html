02 · Базовые понятия

Ошибка, дефект, сбой — это не одно и то же

ERROR

Ошибка человека

Неправильное действие или решение разработчика, аналитика, тестировщика или другого участника проекта.

Пример Разработчик неправильно понял формулу расчёта скидки.
DEFECT / BUG

Дефект в ПО

Несоответствие программы требованиям или ожидаемому поведению, которое появилось в результате ошибки.

Пример В коде записана неправильная формула.
FAILURE

Сбой

Наблюдаемое неправильное поведение работающей системы, вызванное дефектом.

Пример Пользователь получает неправильную сумму заказа.

03 · Классификация

Основные виды ошибок

Для начинающего разработчика особенно важно научиться различать три фундаментальные категории.

01

Синтаксические

Нарушены правила языка программирования. Интерпретатор или компилятор не может корректно обработать код.

Код не может быть корректно разобран
02

Ошибки выполнения

Код синтаксически допустим, но проблема возникает во время выполнения программы.

Runtime
03

Логические

Программа запускается, но выполняет не то, что требовалось.

Неверный результат
Главное различие Синтаксическая ошибка мешает корректно разобрать код. Runtime-ошибка возникает при выполнении. Логическая ошибка может вообще не вызвать сообщения об ошибке — программа просто выдаёт неправильный результат.

04 · Синтаксические ошибки

Синтаксис: программа не понимает конструкцию

name = "Иван" print(name
Что произошло? Вызов функции print() не закрыт круглой скобкой. Синтаксическая конструкция незавершена.
Что происходит с программой? До нормального выполнения дело не доходит: интерпретатор обнаруживает проблему при разборе кода.

Типичные причины

  • пропущена скобка;
  • пропущена кавычка;
  • неправильно записан оператор;
  • нарушены отступы в Python;
  • пропущен обязательный символ;
  • неправильно оформлена конструкция.

05 · Ошибки времени выполнения

Runtime Error: код запускается, но выполнение ломается

numbers = [10, 20, 30] print(numbers[5])

Что здесь происходит?

  1. Список создан корректно.
  2. Программа запускается.
  3. Код пытается получить элемент с индексом 5.
  4. Такого элемента в списке нет.
  5. Во время выполнения возникает исключение.

Деление на ноль

x = 10 y = 0 print(x / y)

Несуществующий файл

open("data.txt")

Неправильный индекс

items = [1, 2] print(items[10])
Запомните Runtime Error часто можно исследовать по сообщению исключения, типу исключения и строке, на которой оно возникло.

06 · Логические ошибки

Самые коварные: программа работает, но делает не то

price = 1000 discount = 20 result = price - discount print(result)
Почему это логическая ошибка? Код синтаксически корректен и может выполниться без исключения. Но если discount означает 20%, расчёт выполнен неправильно.

Что должен делать разработчик?

1
Требование Определить, какой результат считается правильным.
2
Факт Получить реальный результат программы.
3
Сравнение Найти расхождение.
4
Причина Найти неправильную логику.
5
Исправление Изменить алгоритм и повторно проверить.

07 · Другие категории

Ошибки бывают не только в коде

DATA

Ошибки данных

Программа получает некорректные, неожиданные или неполные данные.

Пустое поле, неверный формат, отрицательное значение.
UI

Ошибки интерфейса

Интерфейс не соответствует требованиям или неправильно реагирует на действия пользователя.

Кнопка не работает, поле принимает неверный ввод.
API

Ошибки интеграции

Несовместимость или неправильное взаимодействие между компонентами системы.

Неверный формат запроса или ответа.
ENV

Ошибки окружения

Проблема возникает из-за настроек среды, конфигурации или внешних зависимостей.

Путь к файлу, переменные окружения, версия библиотеки.
Профессиональный подход Не нужно сразу считать виноватым код. Сначала определите, на каком уровне возникает проблема: данные → интерфейс → логика → модуль → API → окружение.

09 · Что такое отладка

Отладка — это расследование

Отладка (debugging) — процесс поиска, анализа и локализации причины неправильного поведения программы.

Симптом
Что увидели?
→
Воспроизведение
Повторяется ли?
→
Гипотеза
Почему?
→
Проверка
Так ли это?
→
Локализация
Где причина?

Плохой подход

«Давайте поменяем несколько строк и посмотрим, заработает ли».

Хороший подход

«Сначала определим, где появляется неправильное значение, затем проверим гипотезу».

Главное правило

Меняйте одну причину за раз. Иначе вы не поймёте, какое изменение решило проблему.

11 · Метод №1

Проверка промежуточных значений

До диагностики

price = 1000 quantity = 2 discount = 10 total = price * quantity - discount print(total)

Мы видим только итоговое значение. Но не знаем, что происходило внутри расчёта.

Добавляем диагностический вывод

subtotal = price * quantity print( "subtotal =", subtotal ) discount_sum = subtotal * discount / 100 print( "discount =", discount_sum ) total = subtotal - discount_sum print( "total =", total )
Идея метода Мы превращаем невидимое выполнение программы в последовательность наблюдаемых промежуточных состояний.

12 · Метод №2

Логирование

Что такое лог?

Лог — это запись событий, происходящих во время работы программы.

Запуск
→
Событие
→
Запись

Что можно записывать?

  • начало и завершение операции;
  • значения важных параметров;
  • состояние отдельных этапов;
  • предупреждения;
  • исключения и ошибки.
print("Начало обработки заказа") print("Получена цена:", price) print("Получено количество:", quantity) print("Расчёт завершён")
Для учебных проектов print() удобен для быстрого исследования программы. В реальных проектах для диагностики обычно применяют полноценное логирование.

13 · Метод №3

Breakpoint — точка останова

Breakpoint позволяет временно остановить выполнение программы в определённой строке и изучить её состояние.

Строка 1
→
Строка 2
→
● BREAKPOINT
→
Пауза

Что можно увидеть?

  • значения переменных;
  • текущую строку;
  • стек вызовов;
  • состояние объектов.

Зачем нужен?

Чтобы остановить программу именно там, где нужно исследовать её состояние.

Главный вопрос

«Какие значения находятся в памяти в этот момент выполнения?»

14 · Пошаговая отладка

Debugger позволяет «пройти» программу по строкам

def calculate(a, b): result = a + b return result x = 10 y = 20 total = calculate(x, y) print(total)

Step Over

Выполнить текущую строку и перейти к следующей, не заходя внутрь вызываемой функции.

Step Into

Если строка вызывает функцию — перейти внутрь этой функции и исследовать её выполнение.

Continue

Продолжить выполнение программы до следующей точки останова или завершения.

15 · Методы в одной системе

Как выбрать метод отладки?

Ситуация Что использовать Что хотим узнать
Нужно быстро проверить значение print() Какое значение получила переменная?
Нужно увидеть последовательность событий Логирование Что происходило во время работы программы?
Нужно остановиться в конкретном месте Breakpoint В каком состоянии находится программа?
Нужно исследовать алгоритм по шагам Debugger Как меняется состояние после каждой строки?
Есть исключение Traceback + Debugger Где и при каких условиях возникла проблема?
Правило Не существует одного универсального метода. Хороший разработчик выбирает инструмент в зависимости от вопроса, на который ему нужно получить ответ.
